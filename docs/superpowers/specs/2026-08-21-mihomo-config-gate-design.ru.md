# Конфиг mihomo как код: гейт валидации + канареечная авто-раскатка

**Дата:** 2026-08-21
**Эпик:** `as-5g2`
**Связано:** `as-7oj` (мониторинг доступности сайтов — поставляет роутерные зонды, которые здесь переиспользуются)
**Английская версия:** [2026-08-21-mihomo-config-gate-design.md](2026-08-21-mihomo-config-gate-design.md)
**Статус:** дизайн согласован, не реализовано

---

## 1. Предусловие, о котором никто не знал

Задача исходит из того, что репозиторий содержит конфиг, на котором работают роутеры. Это не так.

Живой шаблон MIHOMO `Default` из панели (`1ef0346d-7989-4e50-88e6-bbe2b99672fc`) был стянут и
структурно сравнён с `mihomo-remnawave-davoyan-rubypass-v2.2.yaml`:

```
ключи верхнего уровня   идентичны
proxies, dns, tun, sniffer, profile, …    SAME
proxy-groups            DIFF
rule-providers          DIFF
rules                   DIFF
```

Живой шаблон **впереди** репозитория:

- две proxy-группы есть только в живом — `📺 YT фон / PiP` и `📺 YT без рекламы`, тот самый
  YouTube-фикс от 2026-08-18, применённый через API;
- расходятся четыре группы — `🎮 Игры`, `💬 Discord`, `📺 YouTube`, `🤖 ChatGPT и AI`;
- одно правило есть только в живом — `IP-CIDR,193.233.75.48/32,DIRECT,no-resolve`, обход для
  de-matrix-1, добавленный под TURN-эксперимент.

Причина структурная, а не разгильдяйство: `push_mihomo_template.py` — **не** загрузчик файла. Он
тянет живой шаблон, переставляет YouTube-группу и патчит обратно. Каждый фикс месяцами
приземлялся прямо в панель, а файлы в репозитории лежали отвязанными черновиками. В самом живом
шаблоне даже висит устаревший комментарий, утверждающий, что он «was never pushed to Remnawave».

**Следствие:** построенный поверх текущего файла push-to-deploy на **первом же прогоне** молча
откатит YouTube-фикс и TURN-обход.

**Решение: сначала сверка.** Закоммитить живой шаблон как канонический файл, убрать
`v2.0`/`v2.1`/`v2.2` в `archive/`, и только потом собирать пайплайн. Первый дифф, который выдаст
гейт, обязан быть честным.

## 2. Как тестировать кандидата, не трогая панель

Шаблон напрямую не запускается — он несёт расширения Remnawave
(`remnawave: {include-proxies: false}`) и заглушку `proxies:`, которую панель наполняет для
каждого подписчика.

**Проверено экспериментально 2026-08-21**, и это несущая находка всего дизайна: `include-all`,
`exclude-filter` и `filter` — **родные поля mihomo**, а не расширения Remnawave. Единственный
специфичный для панели ключ — `remnawave:`. Значит запускаемого кандидата можно собрать целиком
офлайн:

1. взять шаблон-кандидат;
2. заменить его заглушку `proxies:` реальным списком нод из отрендеренной подписки (обычный
   read-only `GET` на `no.watchd0g.dev/<токен>` с user-agent `clash-meta` — 9 нод, 20 групп,
   34 правила, никаких ключей `remnawave`);
3. выкинуть ключ `remnawave:` из каждой группы.

`mihomo -t` на результате отвечает `configuration file test is successful`. Никаких побочных
эффектов для панели, ни один шаблон не становится живым ради теста.

### 2.1 Требования к обвязке, найденные тем, что на них наступили

Три отказа, которые без обработки либо молчаливы, либо вводят в заблуждение:

- **`tun` в обвязке надо выключать.** Ему нужен `NET_ADMIN` и настоящее tun-устройство; тест
  идёт только в userspace.
- **`allow-lan: false` надо переопределять.** С ним mihomo слушает только loopback **внутри**
  контейнера, из-за чего проброшенный порт ведёт в никуда и curl падает за 3 мс с `http=000` —
  что читается как ошибка конфига, но ею не является.
- **Утверждения должны опираться на факт срабатывания правила, а не на HTTP-код.**
  `chatgpt.com` вернул **403** через американскую ноду: Cloudflare отшивает VPS-адрес. Гейт,
  завязанный на HTTP 200, краснел бы по причинам, не связанным с проверяемым конфигом.

### 2.2 Маршрутизация наблюдается точно

С поднятой обвязкой запросы через mixed-порт дают разбираемую атрибуцию — проверено вживую:

```
--> www.youtube.com:443  match RuleSet(youtube)       using 📺 YouTube[🇳🇱 Netherlands-2]
--> chatgpt.com:443      match RuleSet(openai-inline) using 🤖 ChatGPT и AI[🇺🇸 USA-2]
--> yandex.ru:443        match RuleSet(ru-inline)     using ⚪🔵🔴 RU сайты[🇷🇺 Без VPN]
```

домен → сработавшее правило → группа → конкретная нода. Эндпоинт Clash API `/connections` отдаёт
то же самое массивом `chains`. Полный прогон занимает около десяти секунд.

## 3. Гейт

Четыре слоя, каждый ловит класс, недоступный предыдущему:

1. **Синтаксис** — `mihomo -t` на собранном кандидате.
2. **Целостность ссылок** — каждое правило целится в существующую группу; каждый `RULE-SET`
   называет объявленного провайдера; каждый regex в `exclude-filter`/`filter` компилируется;
   нет групп-сирот. Это класс, где переименованная группа оставляет висячее правило.
   *Отложено, не реализовано:* запрашивать каждый URL провайдера и проверять, что он отдаёт
   200. `mihomo_lint.py` этого не делает — слой сегодня полностью офлайновый, а сетевая
   проверка роняла бы гейт на чужих недоступностях, не имеющих отношения к PR.
   Отслеживается как beads `as-w6c`.
3. **Маршруты** — поднять обвязку, прогнать весь список доменов, записать
   домен → правило → группа.
4. **Регрессия** — сравнить эту карту с файлом ожиданий. Именно этот слой отвечает на вопрос
   «починил YouTube — не сломал ли Discord», который и был задан.

### 3.1 Как объявляется намерение

`config/mihomo/routing-expectations.yaml` хранит карту домен → ожидаемая группа. Смена маршрута
означает смену ожидания тем же коммитом, поэтому дифф PR показывает намерение и ревьюер его
видит. Гейт падает на любом отклонении от файла.

Выбрано вместо маркера в commit message, потому что этот репозиторий уже обжигался на том, что
squash-merge теряет трейлер `Regression-Test-Override:`, и вместо вывода намерения из диффа,
потому что перестановка правил меняет маршрутизацию доменов, которых в диффе нет вообще.

Побочная польза: этот файл становится единственным местом, где вообще записано, как маршруты
должны работать. Сейчас это знание не зафиксировано нигде.

## 4. Раскатка

**Триггер:** PR, трогающий конфиг, гоняет полный гейт без раскатки и постит дифф маршрутов
комментарием. Мерж в master гоняет гейт заново и затем раскатывает.

**Порядок раскатки:**

1. `GET` живого шаблона — это и даёт текущее состояние для диффа, и даром кладёт нам в руки
   предыдущий base64.
2. `PATCH` панели кандидатом.
3. Форс-рефреш **только канарейки**, `wrt-zmit` (бывший `wrt-me`) — собственное устройство
   пользователя, поставленное вместо умершего клиентского, так что полчаса кривого маршрута
   стоят там дешевле всего.
4. Проверка на канарейке — живое железо и настоящий OpenClash.
5. Если чисто — форс-рефреш остальных роутеров.

Роутеры и так тянут конфиг сами (`wrt-sh` каждые 60 минут, остальные по cron в 03:00), поэтому
форс — ускоритель, а не механизм. Именно это делает откат ниже действенным.

**Откат при провале канарейки:** восстановить предыдущий base64, форс-рефреш канарейки обратно,
алерт в Telegram, остальные роутеры не трогать. Поскольку остальные тянут только по расписанию и
форса не получали, **клиенты плохой конфиг не видят вообще**.

**Телефоны вне области действия** — по словам пользователя, пушить на них нельзя, они полагаются
на собственное автообновление.

### 4.1 Проверка канарейки не ждёт `as-7oj`

Проверку на канарейке можно запускать сразу по SSH на роутере: спросить его API mihomo о
состоянии пула и прогнать домены из файла ожиданий через mixed-порт, читая совпадение правила из
лога. Она станет богаче, когда приземлится роутерный агент из этапа 2 эпика `as-7oj`, но ждать
его не обязана.

## 5. Чего не делаем

- Пушить конфиг на телефоны.
- Тестировать против живого шаблона, предварительно сделав кандидата живым.
- Требовать HTTP-доступности как условия гейта (см. 2.1).
- Оставлять панель источником правды.

---

## 6. Риски

- **Опасен именно коммит-сверка.** Он определяет «правильное» для всего последующего. Он должен
  быть точным слепком живого шаблона, ревьюиться именно как слепок, и не превращаться в повод
  «заодно причесать».
- **Правки в панели мимо пайплайна** через веб-интерфейс молча вернут расхождение. Стоит
  добавить периодическую проверку дрейфа, сравнивающую живое с репозиторием и алертящую —
  дёшево, когда пайплайн уже есть.
- **Обвязке нужны реальные учётные данные нод** (отрендеренная подписка), чтобы собрать
  кандидата. Тянуть её надо в момент прогона по секретному токену и никогда не писать в артефакт
  или лог.
- **Авто-откат — сам по себе автоматика, которая может сработать не так.** Он намеренно узкий:
  восстановить один заведомо рабочий base64, обновить один роутер, дать алерт.
- **Шум от антибота** на чужих доменах — смягчён тем, что утверждения опираются на совпадение
  правила, а не на ответ.

## 8. Смежная находка в существующих задачах

`as-4ty` («wrt-sh: durable YouTube monitor») висел с пометкой «DURABLE FIX PENDING: подписка всё
ещё отдаёт youtube→RU, следующая скачка откатит ручную правку». Проверено экспериментом на живом
шаблоне — **уже не отдаёт**:

```
[TCP] --> www.youtube.com:443 match RuleSet(youtube) using 📺 YouTube[🇳🇱 Netherlands-2]
```

Нидерланды, а не RU-выход. Источник починен, локальный оверрайд на `wrt-sh` больше не несущий.
Два следствия перед закрытием задачи:

1. `config_update_interval` на `wrt-sh` намеренно держали на 720 минутах, чтобы ручная правка
   пережила клиентский тест. С починенным источником его надо вернуть на 60.
2. Ручная правка `/etc/openclash/Watchdog.yaml` на `wrt-sh` всё ещё расходится с тем, что отдаёт
   подписка. Форс-рефреш из этого эпика её **сотрёт** — безопасно теперь, когда источник верен,
   но проверить это надо **до** первой форсированной раскатки на `wrt-sh`, а не после.
